# 工作流可视化数据引用方案

## 1. 背景

工作流节点之间传递的是结构化数据。底层可以统一表示为 JSON，但普通用户通常不知道：

- SQL 结果位于 `rows`，以及数组下标从 `0` 开始；
- HTTP 正文位于 `body`，字段还可能多层嵌套；
- 应该使用单个值、整行、整列还是完整数组；
- 节点 ID、字段路径和表达式应该怎样拼接。

如果要求用户直接编写 `$.nodes.n2.output.rows[0].token`，变量功能实际上变成了编程功能，学习成本和出错概率都很高。

本方案将变量引用改造成“可视化选择数据”：用户只表达自己想取什么，系统负责生成、保存和执行底层引用。

## 2. 目标

1. 用户不需要理解 JSON、节点 ID、数组下标或表达式语法。
2. 输入任意文本时，键入 `/` 即可选择上游数据。
3. 系统根据真实输出结构自动选择表格、字段树、列表或单值界面。
4. 插入后显示可读变量标签，不直接暴露内部路径。
5. 用户能预览最近一次运行的真实值，并能随时重新选择。
6. 同一套能力覆盖 SQL、HTTP、列表、数据整形、日期和流程控制节点。

## 3. 非目标

- 第一阶段不提供自由编写 JavaScript、JSONPath 或复杂表达式的能力。
- 不把所有运行元数据默认展示给普通用户。
- 不依赖每一种节点实现一套独立变量面板。
- 不允许用预览数据替代正式运行时数据。

## 4. 核心概念

### 4.1 用户看到的是“数据引用”

输入框中显示：

```text
[SQL 查询 · 第 1 行 · token]
[HTTP 调用 · 响应正文 · user · name]
[日期计算 · 日期]
```

底层可以保存为：

```text
$.nodes.sql_1.output.rows[0].token
$.nodes.http_1.output.body.user.name
$.nodes.date_1.output.date
```

内部路径只用于执行、调试和兼容旧流程，不作为主要交互展示。

### 4.2 根据数据形态选择界面

统一识别五种输出形态：

| 数据形态 | 示例 | 默认界面 |
| --- | --- | --- |
| 标量 | 文本、数字、布尔值 | 单值卡片 |
| 对象 | HTTP JSON、整形结果 | 可展开字段树 |
| 数组 | 列表处理、循环结果 | 列表选择器 |
| 表格 | SQL、对象数组 | 表格选择器 |
| 运行状态 | 状态码、成功数、是否发送 | 状态字段列表 |

节点只声明输出结构，选择器根据结构渲染，不为每个节点重复开发。

## 5. 总体交互

### 5.1 唤起

用户在支持引用的文本、代码、URL、请求参数、请求头、请求体等输入区域键入 `/`。

变量面板显示当前节点可引用的上游节点：

```text
选择数据

最近使用
  SQL 查询
  HTTP 调用

其他
  手动触发
  日期计算
```

用户继续输入时，按节点名、字段中文名和字段名搜索。没有匹配项时面板自动关闭。

### 5.2 选择

```text
选择上游节点 -> 选择数据区域 -> 选择使用方式 -> 选择具体数据 -> 预览 -> 插入
```

简单节点可以跳过中间步骤。例如日期节点点击“日期”即可插入。

### 5.3 插入

插入后显示不可被普通文本拆开的变量标签。标签支持：

- 单击：重新打开选择器并定位到当前引用；
- 悬停：显示来源、类型和最近一次真实值；
- Backspace/Delete：整体删除；
- 复制粘贴：保留完整引用信息；
- 来源失效：标签变为错误状态并提示重新选择。

## 6. 各类节点交互

### 6.1 SQL 查询

真实运行或结构探测后，以表格展示：

```text
SQL 查询结果                         3 行 x 3 列

       uid       name       token
第1行  123       张三       007xxx
第2行  456       李四       007yyy
第3行  789       王五       007zzz
```

提供四种使用方式：

| 使用方式 | 操作 | 结果 |
| --- | --- | --- |
| 单个值 | 点击单元格 | 第 N 行的某一列 |
| 整行 | 点击行号 | 一条对象数据 |
| 整列 | 点击列头后选择“整列” | 某列的值列表 |
| 表格 | 勾选多个列 | 可用于消息的表格数据 |

行选择支持：

- 第一行；
- 最后一行；
- 第 N 行；
- 按条件查找，例如 `uid 等于 123`。

如果选择“第一行、最后一行、第 N 行”，但 SQL 没有明确的 `ORDER BY`，界面提示“查询结果顺序可能变化”。按条件查找是更稳定的默认推荐。

空结果在运行时返回空值，并由使用该值的字段决定是允许为空、使用默认值还是报错。

### 6.2 HTTP 调用

HTTP 输出分为三个用户可理解的区域：

```text
HTTP 调用
├─ 响应正文
├─ 状态码
└─ 响应头（高级）
```

对象正文显示字段树，同时在右侧显示最近一次真实值：

```text
响应正文
├─ token                  007xxx
├─ type                   007
└─ user
   ├─ uid                 123
   └─ name                张三
```

如果正文是对象数组，自动切换为 SQL 同款表格选择器；如果正文是普通数组，切换为列表选择器；如果正文是文本或数字，直接作为单值插入。

默认隐藏 Cookie、认证信息等敏感响应头。预览内容复用现有脱敏规则。

### 6.3 列表处理与循环遍历

先让用户选择如何使用列表：

```text
取一个值 | 取全部 | 统计数量
```

“取一个值”继续提供：第一项、最后一项、第 N 项、按条件查找。列表元素是对象时可继续展开字段。

循环体内额外显示：

- 当前项；
- 当前序号；
- 当前项的子字段。

循环节点本身的结果显示：结果列表、成功数和失败数。

### 6.4 数据整形与变量赋值

数据整形输出使用对象字段树。变量赋值直接使用用户定义的名称作为一级字段，不展示内部的 `values` 容器。

示例：

```text
变量赋值
├─ customerId
├─ token
└─ reportDate
```

### 6.5 日期计算

使用带示例值的单值列表：

```text
结果日期       2026-08-15
紧凑日期       20260815
月份           202608
时间戳         1786752000
星期           星期六
```

用户点击即可插入，不显示 `value`、`compact`、`unix` 等内部字段路径。

### 6.6 触发节点

手动触发优先显示用户配置的流程入参，例如“客户 ID”“查询日期”，而不是 `$.trigger.*`。

定时触发额外显示：计划执行时间、实际开始时间和运行 ID。运行 ID 放入“运行信息”分组，默认折叠。

### 6.7 条件、汇合和结束节点

- 条件分支：显示“是否命中”，类型表现为是/否。
- 汇合：先选择来源分支，再继续选择该分支的字段；不让用户面对 `branches[0]`。
- 结束节点：作为流程最终输出，不默认出现在上游变量列表。
- 便签：没有运行输出，不参与数据引用。

### 6.8 通知节点

通知节点只在“运行信息”中提供是否发送、内容字节数和目标，不作为普通业务数据优先展示。

## 7. 数据预览与结构学习

### 7.1 数据来源

选择器按以下优先级获取结构和示例值：

1. 最近一次成功运行的真实输出；
2. 用户固定的调试数据；
3. 节点结构探测结果；
4. 节点注册表中声明的静态输出结构。

### 7.2 未运行状态

动态输出尚未知时，不展示猜测字段，显示：

```text
还不知道这个节点会返回哪些数据
[运行此节点]
```

只有声明支持结构探测的节点才显示“获取字段”操作。不能探测的节点不显示无效按钮。

### 7.3 预览限制

- SQL 和数组默认预览前 20 行；
- 大文本截断显示，可展开查看；
- 密钥、Token、Cookie 等敏感值默认打码；
- 预览明确标注运行时间，避免用户误以为是实时值；
- 预览数据不写入流程配置。

## 8. 引用模型

建议内部将引用保存为结构化数据，而不是只保存一段不可理解的字符串：

```json
{
  "kind": "reference",
  "sourceNodeId": "sql_1",
  "path": ["rows", 0, "token"],
  "label": "SQL 查询 · 第 1 行 · token",
  "valueType": "string",
  "selection": {
    "mode": "cell",
    "row": { "mode": "index", "index": 0 },
    "column": "token"
  }
}
```

按条件查找示例：

```json
{
  "kind": "reference",
  "sourceNodeId": "sql_1",
  "path": ["rows"],
  "valueType": "string",
  "selection": {
    "mode": "cell",
    "row": {
      "mode": "match",
      "column": "uid",
      "operator": "eq",
      "value": "123"
    },
    "column": "token"
  }
}
```

运行前将结构化引用编译成当前引擎能够执行的表达式。旧流程中的字符串表达式继续兼容，新插入的引用优先使用结构化模型。

## 9. 类型与错误处理

插入前根据目标字段和引用值进行类型检查：

- 文本字段可以接收标量；对象和数组需要用户选择 JSON 格式化或具体字段；
- 数字字段只接受数字，文本数字可以明确转换；
- URL、请求头和 SQL 参数不允许直接插入完整对象或数组；
- 表格只允许插入支持表格渲染的消息类型；
- 找不到匹配行时可以选择返回空值、使用默认值或让节点失败。

错误提示必须使用用户语言：

```text
“SQL 查询 · token”没有找到 uid 等于 123 的数据
```

不要只显示：

```text
Cannot resolve $.nodes.sql_1.output.rows[0].token
```

## 10. 组件设计

建议拆分为以下通用组件：

- `DataReferencePicker`：统一入口、搜索、面包屑和确认操作；
- `NodeSourceList`：展示可引用的上游节点；
- `ObjectFieldTree`：对象字段树；
- `DataTablePicker`：表格、单元格、行和列选择；
- `ArrayValuePicker`：数组的第一项、最后一项、第 N 项和条件查找；
- `ScalarValueList`：标量字段列表；
- `ReferenceChip`：输入框中的可视化引用标签；
- `ValuePreview`：真实值、类型、运行时间和脱敏展示。

组件读取统一的输出描述，不直接判断具体节点类型。节点可通过少量展示元数据覆盖名称、隐藏内部字段或指定敏感字段。

## 11. 分阶段实施

### 第一阶段：解决最主要的使用问题

1. SQL 单元格、整行、整列和表格选择。
2. HTTP 响应正文字段树。
3. 输入框使用可视化变量标签。
4. 最近一次运行值预览。
5. 保持现有表达式执行能力和旧流程兼容。

### 第二阶段：统一数组和对象

1. 列表处理、循环结果和数据整形接入通用选择器。
2. 支持第一项、最后一项、第 N 项和按条件查找。
3. 增加目标字段类型检查和转换提示。

### 第三阶段：完善可维护性

1. 结构化保存引用。
2. 引用来源变更后的自动迁移和失效提示。
3. 默认值与缺失值策略。
4. 引用使用位置查询。
5. 高级模式下查看底层表达式。

## 12. 验收标准

1. 新用户不查看说明文档，可以从 SQL 结果中选择第一行的 `token`。
2. 新用户可以从 HTTP JSON 中选择任意嵌套字段。
3. 用户界面不要求输入节点 ID、数组下标或字段路径。
4. 动态字段未知时有明确、可执行的下一步。
5. 选择器不会为不支持探测的节点显示探测按钮。
6. 插入后的变量可以重新选择、删除、复制和预览。
7. 节点删除、字段消失或类型变化后，引用能被明确标记为失效。
8. 旧流程中的已有表达式仍能正常加载和运行。
9. Token、Cookie 和认证信息不会在预览中明文泄露。
10. SQL 没有稳定排序时，按行号取值会显示顺序风险提示。

## 13. 推荐决策

采用“斜杠唤起 + 自动识别数据形态 + 可视化选择 + 变量标签”的统一方案。

第一阶段优先完成 SQL 和 HTTP，因为这两类节点同时覆盖表格、对象、数组和标量，能够验证核心模型。列表、循环、整形和变量赋值随后直接复用相同组件，不再增加新的变量交互范式。
