## 当前整站审计（按页面，全部有代码出处）

### 旅程 A：新用户第一次进来

1. `Home` 空列表：大菱形 + 「从一个模板开始最快」，但真正的业务模板只有 `scheduled-sql` 一条，其余三张是「只有触发器的空流程」（`src/lib/templates.ts`）。
2. 点「+ 新建流程」又弹出几乎同一套卡，分组名叫「从零开始 / 从模板导入」，和空状态文案打架。
3. 选「手动触发」后 `App.createAndOpen` 走 `window.location.assign`，整页刷新，中间是光秃的「正在打开流程…」（`App.tsx:235-271`）。
4. 进编辑器：一张触发器卡 + 顶中「添加第一个步骤」三颗按钮。没有 `Tab`。顶栏同时出现 mock/已连接、校验通过、添加入参、撤销、更多、保存、发布、运行。
5. 点顶栏红色「运行」—— **只是打开底部面板，并不跑**（`Toolbar.tsx:351-356` → `setRunPanelOpen`）。真正的运行在面板里再点一次，且校验失败时按钮 disabled、title 才说原因。

**失败点：** 「运行」名实不符；新建分类骗人；进编辑器像进了控制室。

### 旅程 B：每天改一条已有日报

1. 首页卡片只显示：emoji、名字、触发类型、节点数、更新时间。**没有**上次运行成败、发布时间、几点跑、用了哪些节点（`Home.tsx` `FlowCard`）。
2. 「昨天为什么失败」在卡片 ⋯ → 运行记录，第三层。
3. 搜索只匹配名字（`Home.tsx:108-111`），不能筛「定时 / 失败 / 只在本机」。
4. 有流程之后，模板从主画面消失，只能再点新建。

### 旅程 C：配 SQL 并发企微

已有 quickstart 一键加 SQL，引用胶囊也在做。仍贵的是：

- Inspector 标题下挂 `sql.query` 和 `n2` 两个 `<code>`（`Inspector.tsx:124-128`）。
- 「输出结构」展开后是列名芯片 + **整份 output JSON Schema**（`Inspector.tsx:210-213`）。
- 「错误处理 / 幂等 / 重试」对业务同学是噪声，却和 SQL 编辑器平级。
- 顶栏「添加入参」实际打开的是「流程设置」（名称 + 入参），按钮却画了 plus（`Toolbar.tsx:218-229`）。
- FlowInspector 底部 tip 还在教「画布左上角添加节点」（`Inspector.tsx:290-293`），和 quickstart / 连线 `+` 重复且过时。

### 旅程 D：跑失败了要看懂

- 运行历史左侧是 `run_xxx` 这种 id（`RunPanel.tsx:187`）。
- 分步行同时显示节点名、`n2`、live、📌、错误原文。
- 失败错误经常带 `$.nodes...`（Track 0 Task 6 已列）。
- 首页没有「这条上次失败」的红点，必须进编辑器或 ⋯ 记录。

### 技术债会直接变成体感

| 现象 | 出处 |

## 目标信息架构（做完后用户应看到的）

```
首页
  搜索 + 触发类型筛选
  主按钮：新建（模板优先，空白次之）
  卡片：名字 / 何时跑 / 上次运行 ● / 节点摘要
  主操作：打开；次操作：运行记录、复制、删除

编辑器顶栏（从左到右，最多 6 个落点）
  返回 | 流程名 + 保存状态 | 问题 | 发布状态 | 运行
  其余进 Cmd+K 和「更多」：入参、JSON、版本、撤销、整理

画布
  空：触发器大卡「更换方式」+ 三颗第一步
  Tab / 双击空白 = 加节点
  单击节点 = 右侧只含「每次要改的字段」
  双击 = 看这次的数据（NDV 默认输出栏）

底部
  运行面板默认关
  点「运行」：无入参且校验过 → 直接跑并打开面板
  有必填入参 → 打开面板并聚焦第一个空项，不要假装已经跑了
```

## Proposed approach

先改**名实不符和整页刷新**（半天内体感最大），再改首页卡片，再收顶栏，再清 Inspector 工程师字段。Track 0 的胶囊/SchemaForm 可并行，互不挡。

默认决策（实现时不要再问）：

1. 顶栏「运行」在能跑时直接跑；不能跑时打开面板并说明原因。
2. 「添加入参」改名为「流程」或齿轮，不再用 plus。
3. 首页卡片增加上次运行状态；没有数据就显示「还没跑过」，不要留空。
4. 用 `history.pushState` + 现有 `routeFromPath` 做同页切换，不引入 react-router。
5. Toast 只用于成功/后台失败；破坏性操作仍用模态确认（可继续 `confirm`，不要为审美重写确认框，除非顺手有 `ConfirmDialog`）。

### Task R1: `requestRun()` —— 「运行」的唯一入口

**Objective:** 顶栏、命令栏、快捷键走同一个函数，行为可测。

**Files:**
- Create: `src/lib/runRequest.ts`
- Modify: `src/store.ts`（可只 export 包装，不把 UI 判断塞进 store）
- Modify: `src/components/Toolbar.tsx` 运行按钮
- Test: `test/runRequest.test.ts`

```ts
export type RunRequest =
  | { action: 'start'; trigger: Record<string, unknown> }
  | { action: 'open-panel'; reason: 'missing-inputs' | 'invalid'; messages: string[] }
  | { action: 'stop' }

export function decideRunRequest(input: {
  running: boolean
  flowInputs: FlowInputField[]
  form: Record<string, string>
  problems: string[]
}): RunRequest
```

规则：

- `running` → `stop`
- `problems.length > 0` → `open-panel` + 原因
- 有未填必填入参 → `open-panel` + `missing-inputs`
- 否则 → `start`（trigger 从 form 转换，无入参则 `{}`）

Toolbar：

```
onClick={() => {
  const d = decideRunRequest(...)
  if (d.action === 'stop') stopRun()
  else if (d.action === 'start') { setRunPanelOpen(true); void startRun(d.trigger) }
  else { setRunPanelOpen(true) /* 面板自己高亮原因 */ }
}}
```

按钮文案：运行中 = 「停止」；否则 = 「运行」。不要再 `btn--active` 表示「面板开着」。

**Commit:** `fix(run): primary Run button actually runs`

## Risks, tradeoffs, open questions

| 风险 | 处理 |
|---|---|
| `pushState` 漏了刷新/分享 | 保留现有 URL 形状 `/workflows/:id`，刷新仍走 `routeFromPath` |
| 顶栏「运行」直接跑，用户以为还在预览 | 无入参才直接跑；有入参先开面板。title 写「运行当前草稿，不是已发布版」 |
| 列表 last-run 没有 API | 先显示「还没跑过」，不要假数据；有再利用现成 runs 接口，另开任务，不阻塞 H2 其它字段 |
| toast + savestate 双重提示 | 保存失败只留 savestate 可点；toast 用于复制/上传这种离开现场的动作 |
| 和 Track 0 抢同一文件 | Inspector / Toolbar / Canvas 会撞车。按上面顺序，同一文件的任务由同一人连续做完 |

**Open questions（已拍板）：** 不做文件夹、不做 react-router、不做确认框重设计、不做移动端。
